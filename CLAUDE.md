# CLAUDE.md

## What this is

A Nix flake that wraps Claude Code with its configuration: `claude` with this repository's `sources/.claude` (settings, rules, commands, plugins, the git allowlist and the format hook) and, on its PATH, the tools those call (the `claude-<x>` helpers under `packages/`, the Playwright MCP, language servers, formatters, `git-shim` and `git-allowlist-hook`), plus `claude-launch`, which starts it with its profile prepared, its plugins loaded and the whole process sandboxed. `nix run github:Runeword/claude` runs `claude-launch`. [Runeword/terminal](https://github.com/Runeword/terminal) takes it as an input, builds it with `lib.mkClaude` and starts it from its shell functions (`sources/.config/shell/functions/claude.bash` there), which keep only the terminal's own part: tmux windows, leader chords and pickers.

## Common commands

Enter the dev shell first (`nix develop`; direnv does it through `.envrc`): it renders `lefthook-generated.yml` and installs the git hooks. `nix flake check` builds every check; `nix build .#checks.x86_64-linux.claude` runs the wrapper's smoke test alone, and `.#checks.x86_64-linux.claude-launcher` the launcher's.

## Layout and outputs

- `package.nix` is the package: the bare wrapper (`wrapper.nix`, `bin/claude`) and the launcher (`launcher/`, `bin/claude-launch` and `bin/claude-plugins`) joined, `meta.mainProgram = "claude"`, and the default plugins' list. `flake.nix` builds it through `lib.mkClaude { system, configPath ? ./sources, git ? null, lefthookHooks ? null }`, for `packages.default` and for consumers.
- `wrapper.nix` is the bare wrapper: a `symlinkJoin` of `claude-code` and the config, with permeance's compiled launcher, which sets claude's PATH, `CLAUDE_GIT_ALLOWLIST_CONFIG`, `--settings` and the other flags. It is what runs inside the sandbox, and what scripts call. It takes the system, not a package set, and builds from this flake's nixpkgs (which a consumer can have follow its own). `git` is the git the shim runs once the allowlist lets a command through (nixpkgs' by default; the terminal passes its wrapped one). `lefthookHooks` is a `lefthook-hooks.nix` whose format hooks' tools go on claude's PATH for `claude-format` (this repository's `devshells/lefthook-hooks.nix` by default; the terminal passes its own).
- `packages/<x>/` holds the Go binary `claude-<x>`: the directory drops the prefix, while the `go.mod` module, which names the binary, and `pname` keep it. All are stdlib-only (`vendorHash = null`). `packages.claude-sessions` is also an output of its own, for the shell functions that run it outside claude; `packages.playwright-mcp` is nixpkgs' Playwright MCP behind a wrapper that gives it a scratch home.
- `sources/.claude` is the config, bundled into the wrapper's `$out` by `lib/files.nix`'s `mkConfig`. What a launch needs that a flag can't carry is in it: the model, the WebSearch/WebFetch allow rules and `CLAUDE_CODE_SYNTAX_HIGHLIGHT` in `settings.json`, the sandbox in each `settings.<os>.json`.
- `launcher/claude-launch.bash` is the launch, in one process (the header lists its steps). Every argument is claude's; the environment says how to start it, as the terminal's tmux command carries it: `CLAUDE_CONFIG_DIR` (default `~/.claude-1`, never `~/.claude`), `CLAUDE_PLUGINS` (default `claude-plugins --default`), `CLAUDE_LAUNCH_VM=1`, `CLAUDE_SANDBOX=0` and the `CLAUDE_SANDBOX_ALLOW_*` opt-ins. It prepares the profile with `claude-profile` (`packages/profile`): the config's `rules/` and `commands/` linked, `settings.json` merged with this OS's overlay and written in place, and what a session could plant for the next one dropped, the project's `settings.local.json` included. `claude-profile` works through an `os.Root`, so a planted link can't take it outside the profile, and only touches a profile it owns: one it made, an empty one, or one holding its `.claude-launch` marker (`touch ~/.claude-N/.claude-launch` adopts an existing one). Then it runs claude under claude-sandbox on Linux, claude-macos for a macOS session holding a credential, or claude-vm (from PATH), every command by store path, with `--allow-dangerously-skip-permissions` only where the sandbox or the microVM confines the whole process. `launcher/default.nix` builds it with `writeShellApplication`, which shellchecks it, and takes the stand-ins the tests hand in.
- The wrapper replaces Claude Code's built-in Explore agent with a read-only one, passed to every session with `--agents`: `packages/explore-guard/agent.nix` and `prompt.md` define it, next to `claude-explore-guard`, the guard its `PreToolUse` hook on Bash runs by store path with `onFailure: "block"`. The agent ships with its guard, rather than loading live from `sources/` like the rest of the config, so a running claude never loads an agent its own build doesn't enforce; changing its prompt therefore takes a rebuild. Claude Code refuses to start on an `--agents` value it can't load.

## Live config and the sandbox

The bare wrapper's launcher uses a permeance namespace of its own, `CLAUDE_SOURCES`: `CLAUDE_SOURCES_ROOT=/path/to/sources` makes claude read its config from that live tree, with no rebuild (`CLAUDE_SOURCES_TREE` is what the launcher resolved; `CLAUDE_SOURCES_ROOT_IGNORE` sets the live tree aside). The `PERMEANCE_ROOT` of the tree a shell around claude runs from, such as the terminal's, reaches claude's children untouched rather than redirecting claude to a tree with no claude config. Unset, claude reads the copy bundled in the store, which no session can edit. `claude-launch` reads the same variable (`claude_tree`), so the profile it prepares and the plugins it loads come from the tree claude runs with.

Under the terminal's claude-sandbox, a live tree is read-only to a session started anywhere but in it. Nothing pins it in a session started in this checkout, which can write everything in it: with `CLAUDE_SOURCES_ROOT` pointing here, such a session could widen its own `git-allowlist.toml`, which the git shim re-reads on every call, and change the `settings.json`, plugins and rules later sessions load. So leave `CLAUDE_SOURCES_ROOT` unset where sessions start in this repository (its bundled copy is what claude runs then), or edit `sources/` from a plain terminal.

`permeance` and `claude-sandbox` are private and fetched over ssh, with the ref spelled out, as in the terminal; a consumer has them follow its own inputs.

## Testing

`wrapper.nix`'s `passthru.tests.smoke` (the `claude` check) tests the wrapper behaviourally, through `permeance.tests.mkSmoke`: claude starts and reads its config from `CLAUDE_SOURCES_ROOT` and not `PERMEANCE_ROOT`, every command `settings.json` and the plugins name resolves on claude's PATH, `claude-statusline` renders a fixed payload (a change to its output updates that expected line), `claude-format` runs a repository's own lefthook formatters and only those, the Explore agent loads with its guard, and the Playwright MCP starts with no way out of its wrapper's settings. A change to the config or to what the wrapper puts on claude's PATH extends that test. `launcher/test.sh` (the `claude-launcher` check) runs the launcher with stand-ins for claude, bwrap and pass (`launcher/tests.nix`): the profile it prepares and refuses, the plugins and the secret, the open-session lock, and what confines claude, through a dry run of the real claude-sandbox on Linux, and the Darwin branch, with the real claude-macos. A change to the launch extends it. A Go binary ships its `main_test.go` beside `main.go`, table-driven with stdlib `testing`: `buildGoModule` runs `go test` in its check phase, so it runs on every build. `lefthook-config` checks that the committed `lefthook-generated.yml` is what the dev shell renders. CI (`.github/workflows/ci.yml`) runs `nix flake check` on Linux and macOS, reading the two private inputs through a GitHub App token, as the terminal's CI does.

The terminal's checks cover what this repository can't see: its `claude` and `claude-launcher` checks run these tests on the terminal's build, its `claude-sandbox` check dry-runs the sandbox launchers against its tree, and its `zsh-claude` topic asserts that its shell functions and this package agree (`.shellcheckrc` and `shell-lsp`'s exclusions, the command it hands tmux). A change here that touches one of those (a variable `claude-launch` reads, a plugin renamed) needs the matching change there.
